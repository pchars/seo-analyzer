# SEO Analyzer Pro

Проверка одной страницы: SEO-разметка, технические заголовки и то, что можно честно сказать о скорости без браузерного прогона.

Браузер не может скачать чужой сайт из-за CORS, поэтому страница запрашивается сервером приложения. Оценка считается в браузере по полученному снимку. История проверок хранится в `localStorage` и на сервер не отправляется.

## Что измеряется

39 проверок в трёх группах.

- Скорость: TTFB и время загрузки HTML, цепочка редиректов, размер документа, число ресурсов в разметке, чужие домены, форматы картинок, размеры img, кеш и сжатие, минификация по имени файла, скрипты в `head`, веб-шрифты.
- SEO: title, description, заголовки, ссылки внутри сайта, robots.txt и доступ страницы, sitemap, viewport, canonical, alt, Schema.org, Open Graph, индексация, хлебные крошки.
- Техника: HTTPS, версия TLS, HSTS, HTTP/2 по ALPN, заголовки безопасности, флаги cookie, favicon, DOCTYPE и язык, размер DOM, кодировка, смешанный контент, доступность.

## Запуск

Нужен Node.js 20 или новее.

```bash
npm install
npm start
```

Откройте `http://localhost:3000`. Порт меняется переменной `PORT`.

```bash
npm test
```

## Публикация

Сервису нужен процесс Node, а не только статический хостинг: без сервера анализатор не сможет запросить чужую страницу.

```bash
docker build -t seo-analyzer .
docker run --rm -p 3000:3000 seo-analyzer
```

Так же подходит любой хостинг, где запускается `npm start` и открыт `PORT`: VPS, Railway, Render, Fly.io. Поставьте `NODE_ENV=production`. Не задавайте `ALLOW_PRIVATE_TARGETS` на публичном сервере: этот флаг пускает запросы во внутреннюю сеть и нужен только тестам.

Переменные:

| Переменная | Значение |
| --- | --- |
| `PORT` | Порт, по умолчанию 3000 |
| `HOST` | Адрес, по умолчанию `0.0.0.0` |
| `RATE_LIMIT` | Запросов к API с одного IP за минуту, по умолчанию 10 |
| `MAX_CONCURRENT` | Сколько проверок идёт одновременно, по умолчанию 2 |
| `RATE_LIMIT_FILE` | Файл общего счётчика, если запущено несколько процессов |
| `TRUST_PROXY` | `1`, если перед процессом один обратный прокси. Тогда лимит берёт `X-Real-IP` или последний адрес в `X-Forwarded-For`. Без флага заголовок игнорируется, чтобы его нельзя было подделать |
| `ENABLE_BROWSER` | `1` выполняет JavaScript страницы. При `npm start` включается само |

Для страниц, которые собираются скриптами, нужен Chromium той же версии, что и `playwright-core`:

```bash
npx --yes playwright@1.49.1 install chromium
```

Без него сервис всё равно проверяет HTML-ответ. PDF собирается на сервере шрифтом с кириллицей и содержит оценку, каждую проверку и рекомендации.

## API

`GET /api/inspect?url=https://example.com` — снимок страницы. Внутренние адреса, редиректы на них и адреса с логином отклоняются. Ответ обрезается на 1.5 МБ, ожидание — 12 секунд. Одновременно выполняется не больше `MAX_CONCURRENT` таких запросов.

`POST /api/pdf` — PDF по JSON уже посчитанного отчёта. Тело запроса не больше 1 МБ.

## Что сознательно не входит в оценку

Twitter Card не считается отдельно: при заполненном Open Graph социальная сеть и так может собрать превью. Service worker, preload и отдельная проверка «современных форматов» убраны, потому что они повторяли другие пункты или снижали балл обычным сайтам. Вместо них считаются индексация, кодировка, смешанный контент и размеры изображений.

## Границы сервиса

- Страницы на чистом JavaScript проверяются после отрисовки, только если установлен Chromium и `ENABLE_BROWSER=1`. Иначе остаётся HTML-ответ.
- Лимит запросов в памяти относится к одному процессу. Несколько процессов делят лимит через `RATE_LIMIT_FILE`. За прокси включите `TRUST_PROXY=1`, иначе все посетители выглядят как один адрес.
- Поток пакетов на сам порт останавливает хостинг или сеть перед процессом. Приложение ограничивает только дорогие вызовы: 10 запросов к API в минуту с адреса и две проверки одновременно.
- PDF — текстовый отчёт на нескольких страницах, не снимок экрана.
